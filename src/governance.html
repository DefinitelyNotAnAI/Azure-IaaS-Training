Governance & Operations Overlay

Instructor-led discussion — how enterprise controls wrap around the IaaS resources you just built.

From individual resources to managed workloads

In the three labs today you created each IaaS resource in isolation. In a production environment, those same resources sit inside a layer of governance and operational tooling that enforces consistency, security, and cost control automatically — without touching each resource individually. This section is your instructor's walkthrough of that overlay.

Azure Policy — enforce configuration at scale

Azure Policy lets you define and enforce rules across your entire estate using three effect types:

  • Deny — blocks non-compliant deployments before they are created (e.g. no public IPs on VMs, only approved regions, minimum TLS version on storage).
  • Audit — flags non-compliant resources for review without blocking them — useful for discovering drift without disrupting existing workloads.
  • DeployIfNotExists / Modify — automatically remediates non-compliant configurations (e.g. install the Azure Monitor agent on every new VM, enable diagnostic settings on storage accounts).

Policy initiatives group related policies into a single assignment — common examples include the Microsoft Cloud Security Benchmark and custom regulatory baselines assigned at the management group level so every subscription inherits them.

Cost management & tagging

Every resource you create should carry metadata that enables accurate showback and chargeback across business units:

  • Required tags (enforced by Policy at creation time): environment, cost centre, workload owner, application name. Non-compliant resources are denied or auto-tagged.
  • Azure Cost Management: filter actual spend by tag to generate per-workload or per-team cost reports; set budgets with email or action-group alerts when thresholds are crossed.
  • Azure Advisor: surfaces idle VMs, under-used disks, unattached public IPs, and reserved-instance savings opportunities — a free, automated cost and performance review.

Monitoring & security posture

  • Azure Monitor + VM Insights: CPU, memory, disk throughput, and network metrics without manual configuration on supported images; dependency maps show running processes and cross-VM network connections.
  • Log Analytics workspace: centralised log aggregation — Windows Event logs, Linux syslog, NSG flow logs, and activity logs all shipped to a single queryable store using KQL.
  • Microsoft Defender for Cloud: unified security posture score across the IaaS estate; actionable recommendations for exposed management ports (RDP/SSH), missing OS patches, unencrypted disks, and misconfigured NSGs.
  • Microsoft Sentinel (optional): SIEM and SOAR that ingests Azure Activity logs, sign-in logs, and VM security events for threat detection, hunting, and automated incident response.
