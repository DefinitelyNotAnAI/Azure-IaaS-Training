Part 3 — Agent Scaffold

Create a Foundry agent and connect it to your Fabric Data Agent via the Microsoft Fabric tool.

Architecture recap

Here's what you're about to build and how the pieces connect:

  1. Your Fabric Data Agent (built in Part 2) — a natural-language interface grounded on your slot's Eventhouse data. It translates questions → KQL → answers.
  2. Your Foundry agent (this challenge) — the reasoning layer. It receives your questions, calls your Data Agent via the Microsoft Fabric tool, correlates the answers across the 5 use cases, and generates insights.

The Foundry agent doesn't run KQL directly — it delegates data retrieval to your Data Agent and focuses on reasoning, correlation, and explaining "what this means for the customer."

Prerequisite — Foundry project

You need access to an Azure AI Foundry project to create agents. The facilitator will provide:

  • The URL to the shared Foundry project (Open Foundry button above, or ask the facilitator).
  • Confirmation that a Fabric workspace connection has been added to the project (required for the Fabric tool).
New to Foundry? Azure AI Foundry is the portal for building and hosting AI agents. Think of it as the Azure portal, but for AI agents. Your agents run on an Azure OpenAI deployment in the shared Foundry hub.

Must-do — Create your Foundry agent (portal path)

  1. Open Azure AI Foundry at ai.azure.com (or use the button above).
  2. In the left nav, click Agents, then click + New agent.
  3. Give your agent a name: workshop-agent-userXX. Select the shared gpt-4o (or the model the facilitator specifies) as the deployment.
  4. Under Instructions, paste the starter system prompt below (copy button provided). You'll refine it in Challenge 2.
  5. Under Tools, click + Add → Microsoft Fabric.
    • Select the Fabric workspace connection (the facilitator will have pre-connected the workspace).
    • Under Select Data Agent, find and select workshop-agent-userXX — the Data Agent you created in Part 2.
  6. Click Save.
CLI alternative (azd): If you prefer code-first, the facilitator can provide the scaffold command. The portal path above is equivalent and doesn't require any local tooling.

Starter system prompt

Copy this into your agent's Instructions field. You'll refine it in Challenge 2 once you see how the agent behaves:

You are an AI agent that helps an application owner understand how system behaviour is driving customer-reported issues, and what to do about it.

You have access to a data tool called Microsoft Fabric that connects to the workshop data layer for slot <>. Use it to retrieve:
- Telemetry data: per-operation metrics (latency, errors, throughput) from the legacy system
- Support ticket data: customer-reported issues describing their experience

When answering questions:
1. Always retrieve relevant data from your Fabric tool before answering.
2. Correlate telemetry patterns with ticket patterns — don't just describe one plane in isolation.
3. Identify whether customer complaints correspond to real system anomalies.
4. Call out discrepancies: if tickets exist without telemetry anomalies (blind spot) or vice versa.
5. Be specific: name services, timestamps, affected tenants, and IncidentIds where available.
6. Conclude with a clear statement of what happened and what it means for the customer.

Must-do — Test the Fabric tool connection

In the Foundry agent playground (the chat panel on the right), send this test question to verify your agent can reach your Fabric Data Agent:

"What was the average latency in the last 2 hours, and how many support tickets were raised in the same window?"

A working response will cite specific numbers pulled from your Eventhouse + Lakehouse data. If the agent responds with "I don't have access to data" or similar, the Fabric tool is not connected — check that you selected your Data Agent correctly in step 5.
