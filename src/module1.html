Module 1 — Networking

Virtual networks, subnets, and the routing foundation for everything else in Azure IaaS.

What you're about to do

You will create a Virtual Network (VNet) in your assigned resource group — a pre-provisioned, RBAC-isolated RG in the workshop subscription. This is a real Azure deployment, not a simulation.

  • Create VNet with address space .
  • Add subnet workload — use the first /26 block of your CIDR.
  • Review the default system routes Azure attaches automatically.

How it fits into enterprise Azure

In an Azure Landing Zone deployment, each workload team owns a spoke VNet with a dedicated, non-overlapping address space. Your spoke today is the CIDR shown in the banner above.

  • Spoke VNets peer back to a central hub VNet (10.0.0.0/16) for shared services and internet egress.
  • Subnets segment the spoke into functional tiers (web, app, data), each with its own NSG.
  • User-Defined Routes (UDRs) force east-west traffic through the hub firewall for inspection.

Lab steps — Create your VNet

  1. Open the portal link in the banner above. You should land on your resource group.
  2. Click + Create and search for Virtual network. Click Create.
  3. On the Basics tab, fill in the Instance details section:
    • Resource group: (already selected)
    • Virtual network name:
    • Region: East US 2 (match the hub)
  4. Click Next to advance to the Security tab. Leave all options unchecked — Virtual network encryption, Azure Bastion, Azure Firewall, and Azure DDoS Network Protection should all remain Disabled. We'll access VMs through the hub's Azure Bastion in Module 3.
  5. Click Next to advance to the Address space tab:
    • The portal pre-fills a default address block. Click the pencil (edit) icon next to it and update: set Starting address to and Size to the prefix of your assigned CIDR.
    • A default subnet is auto-created inside the block. Click its pencil icon and update:
      • Name: workload
      • Starting address: same starting address as your block
      • Size: /26
    • Click Save to confirm the subnet.
  6. Click Review + Create, then Create. Deployment takes under 30 seconds.
