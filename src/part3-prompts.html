Part 3 — Agent Prompts

Run your agent through the 5 use cases and investigate the planted incident scenario.

The 5 use cases

Your agent must be able to answer questions across five types of analysis. Work through them in order — they build on each other and together they answer the key question: "What happened, who was affected, and how do we know?"

Use caseThe question it answers
1. Root cause & correlationWhat system event caused the support ticket spike?
2. Noise vs signalAre these tickets all describing the same underlying problem?
3. Customer impactWhich customers or tenants were affected, and how severely?
4. Change impact detectionDid a deployment or configuration change correlate with the issue?
5. Blind spot detectionIs there a mismatch between what monitoring shows and what customers report?

Use case 1 — Root cause & correlation

Send this prompt to your Foundry agent in the playground. Note: the agent should retrieve correlated data from your Fabric Data Agent and identify a specific spike window.

"I'm seeing a spike in support tickets from customers complaining about slowness. Look at the last few hours of data and tell me: was there a corresponding latency spike in the system telemetry? If so, when did it start, which service was affected, and how many customers filed tickets during that window?"

What good looks like: The agent names a specific time window, a specific service, cites the average latency during the spike, and the count of tickets. It may also mention an IncidentId if the chaos engine tagged the events.

Use case 2 — Noise vs signal

"Looking at the support tickets from the last 2 hours, are there multiple distinct issues or are they all describing the same underlying problem? Group similar tickets and tell me if there is one root cause or several."

What good looks like: The agent clusters tickets by description/category and concludes "these are all describing the same incident" or identifies 2–3 distinct clusters. If your Data Agent's instructions mention IncidentId, the agent should use it to group related tickets.

Tip: If the agent gives a vague answer, refine your Data Agent's instructions to explicitly describe the IncidentId field and its role in linking tickets to incidents.

Use case 3 — Customer impact

"Based on the support tickets during the last major latency spike, which customer tenants were most affected? List them by ticket volume and tell me whether any tenant filed tickets across multiple incidents or just one."

What good looks like: The agent lists specific tenant names, their ticket counts, and ideally notes whether any tenant appears in multiple incident windows (repeat impact). This demonstrates the agent connecting system issues to customer experience.

Use case 4 — Change impact detection

"Was there any unusual system event — like a deployment, configuration change, or error burst — that preceded the support ticket spike? Look for events in the telemetry that could explain what triggered the customer complaints."

What good looks like: The agent identifies the anomaly window from Telemetry (high latency, elevated ErrorCount, IsAnomaly = true) and connects it temporally to the ticket burst. Ideally it surfaces the IncidentId of the planted "bad deployment" event.

This is the key use case. The planted root cause in this hackathon is a simulated "bad deployment" — the agent should identify the anomaly window and link it to the customer tickets. Keep this answer — you'll compare it to the ground-truth in Challenge 3.

Use case 5 — Blind spot detection

"Were there any time windows where customers filed support tickets but the telemetry showed no anomaly — i.e., a customer perception problem that monitoring missed? Conversely, were there any windows where telemetry showed degradation but no tickets were filed yet — an early warning sign?"

What good looks like: The agent runs both the blind-spot query (SlotBlindSpots_userXX) and the early-warning query and reports findings for each pattern. This demonstrates the agent understanding the difference between objective and subjective data planes.

Stretch — Refine your system prompt based on results

After running all 5 use cases, review your agent's answers and identify gaps. Common improvements:

  • Agent gave vague answers: Add more context to instructions about what IncidentId means and how to use it.
  • Agent didn't use the Fabric tool: Add "Always call your Fabric data tool before answering any question about system behaviour or customer tickets" to instructions.
  • Agent named wrong service: Add the service names from your Telemetry to the instructions so the agent knows your system's vocabulary.
  • Agent didn't connect the two planes: Add "Always compare telemetry data and support ticket data together, even when only one is mentioned in the question" to instructions.

After refining, re-run use case 4 (the key one). If the agent now correctly identifies the anomaly window and its customer impact, you're ready for Challenge 3.
