Module 3 — Compute

Deploy a Windows Server VM into your spoke VNet. The legacy support app will auto-install on your VM and begin emitting telemetry and support signals.

What you're about to do

You will deploy a Windows Server 2022 VM into the workload subnet of your spoke VNet. The VM has no public IP address, simulating how enterprise IaaS VMs are deployed in production.

  • Create VM (Standard_D2ads_v5, Windows Server 2022).
  • Attach it to your spoke VNet's workload subnet.
  • Disable public IP.
  • After deployment, the facilitator will install the legacy support app on your VM via a VM Extension — no action required from you. The app will begin emitting telemetry and support signals to the shared data layer automatically.

How it fits into enterprise Azure

In enterprise Landing Zone deployments, IaaS VMs follow a strict network isolation pattern:

  • No public IPs on workload VMs — internet access is routed through the hub Azure Firewall via UDRs. Inbound management access uses Azure Bastion (hub-deployed) over the peering.
  • Availability Zones spread VMs across physically separate buildings for single-region resilience (set during creation).
  • Managed disks — Azure manages the physical storage; you choose SKU (Standard_LRS, Premium_LRS, Ultra).
  • VM extensions (e.g., Azure Monitor Agent, Entra ID login) are deployed via Azure Policy automatically for compliance.
  • Azure Backup and Azure Site Recovery handle point-in-time recovery and cross-region failover.

Lab steps — Create your VM

Preview UI notice: The portal may show a blue banner — "This is a preview of a new Create-VM experience." These steps match that preview wizard. The tab bar now reads: Basics → Disks → Networking → Management → Monitoring → Advanced → Tags → Review + create.
  1. Open the portal link above. Click + Create → Azure virtual machine.
  2. On the Basics tab — Project details:
    • Resource group:
    Instance details:
    • Virtual machine name:
    • Region: (US) East US 2
    • Availability options: Availability zone
    • Zone options: Self-selected zone
    • Availability zone: Zone 1
    • Security type: Trusted launch virtual machines (leave default)
    • Image: Windows Server 2022 Datacenter: Azure Edition — x64 Gen2
      If not shown, click See all images and search for Windows Server 2022.
    • VM architecture: x64 (leave default)
    • Size: Standard_D2ads_v5 (2 vCPU, 8 GiB) — click See all sizes if needed and search D2ads.
    Administrator account:
    • Authentication type: Password
    • Username: workshopadmin
    • Password: choose something you'll remember (confirm it)
    Inbound port rules:
    • Public inbound ports: None — Bastion handles all access
    Deployment recommendations popup: After setting Zone 1 the portal may open a side panel suggesting a different availability zone. Click Cancel to keep Zone 1.
    Click Next: Disks.
  3. On the Disks tab — leave all defaults:
    • OS disk type: Premium SSD (default)
    • Key management: Platform-managed key (default)
    • No data disks needed for this lab
    Click Next: Networking.
  4. On the Networking tab:
    • Virtual network:
    • Subnet: workload
    • Public IP: None — open the dropdown and select None (remove the auto-created IP)
    • NIC network security group: Basic
    • Public inbound ports: None
    • Check Delete public IP and NIC when VM is deleted
    • Load balancing options: None (default)
    Click Next: Management.
  5. On the Management tab — leave all defaults:
    • Metadata Security Protocol: both unchecked
    • Identity / Microsoft Entra ID: unchecked
    • Auto-shutdown: unchecked
    • Guest OS updates — Enable hotpatch: checked (default); Patch orchestration: Azure-orchestrated
    Click Next: Monitoring.
  6. On the Monitoring tab — leave all defaults:
    • Boot diagnostics: Enable with managed storage account (default)
    Click Next: Advanced.
  7. On the Advanced tab — no changes. Click Next: Tags.
  8. On the Tags tab — no changes. Click Review + create.
  9. On Review + create: verify Region = East US 2, Image = Windows Server 2022, Size = Standard_D2ads_v5, Public IP = (none), and VNet = your spoke VNet. Click Create. Deployment takes 2–4 minutes.
  10. Once deployed, click Go to resource on the deployment notification. Confirm the VM blade shows Running in the status field.
    Optional — Bastion access: If your spoke is peered to the hub (see Module 2), you can click Connect → Bastion and sign in with workshopadmin and your password. This is not required for the hackathon to continue.

Verify the legacy app installed

After you mark Module 3 as complete, the facilitator will run a script to install the legacy support app on all participant VMs via a Custom Script Extension. This happens during the next regroup break — no action required from you.

To verify the installation succeeded:

  1. In the Azure portal, open your VM blade ().
  2. In the left menu, under Settings, click Extensions + applications.
  3. Find the extension named InstallLegacyApp. Its status should show Provisioning succeeded.
  4. If the status shows Failed or the extension is not listed, raise your hand — the facilitator will re-run the install script for your slot.
What the app does: The legacy support app simulates an operational system that accepts inbound requests, experiences injected failures at scheduled times, and emits two types of signals to the shared data layer: telemetry (objective — latency, errors, throughput) and support tickets (subjective — simulated user complaints). Parts 2 and 3 will analyse these signals.
