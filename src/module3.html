Module 3 — Compute

Deploy a Windows Server VM into your spoke VNet — no public IP, accessed only via hub Bastion.

What you're about to do

You will deploy a Windows Server 2022 VM into the workload subnet of your spoke VNet. The VM has no public IP address — access is only via Azure Bastion in the hub, simulating how enterprise IaaS VMs are deployed in production.

  • Create VM (Standard_B2s, Windows Server 2022).
  • Attach it to your spoke VNet's workload subnet.
  • Disable public IP (Bastion-only access).
  • Connect via Azure Bastion and verify network connectivity to the hub.

How it fits into enterprise Azure

In enterprise Landing Zone deployments, IaaS VMs follow a strict network isolation pattern:

  • No public IPs on workload VMs — internet access is routed through the hub Azure Firewall via UDRs. Inbound management access uses Azure Bastion (hub-deployed) over the peering.
  • Availability Zones spread VMs across physically separate buildings for single-region resilience (set during creation).
  • Managed disks — Azure manages the physical storage; you choose SKU (Standard_LRS, Premium_LRS, Ultra).
  • VM extensions (e.g., Azure Monitor Agent, Entra ID login) are deployed via Azure Policy automatically for compliance.
  • Azure Backup and Azure Site Recovery handle point-in-time recovery and cross-region failover.

Lab steps — Create your VM

  1. Open the portal link above. Click + Create → Azure virtual machine.
  2. On Basics:
    • Resource group:
    • VM name:
    • Region: East US
    • Availability Zone: Zone 1
    • Image: Windows Server 2022 Datacenter — Azure Edition
    • Size: Standard_B2s (2 vCPU, 4 GiB)
    • Administrator username: workshopadmin
    • Password: choose something you'll remember
  3. On Networking:
    • Virtual network:
    • Subnet: workload
    • Public IP: None (clear the default)
    • NIC network security group: Basic, allow RDP inbound (Bastion handles transport)
  4. On Management: enable Microsoft Defender for Cloud — Free (optional but recommended for the learning experience).
  5. Click Review + Create → Create. Deployment takes 2–4 minutes.
  6. Once deployed, open the VM blade and click Connect → Bastion. Sign in with workshopadmin and your password.
    Bastion is in the hub: The hub-vnet must be peered to your spoke (Module 2) before Bastion can reach your VM. If peering is not yet Connected, complete Module 2 first.
  7. From the VM command prompt, run ping 10.0.2.1 to test connectivity into the hub's shared-services subnet.
