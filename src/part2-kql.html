Part 2 — KQL Correlation

Write a KQL query that joins latency spikes in Telemetry with ticket bursts in Tickets.

The challenge

The core question your Part 3 agent must answer is: "Did a system event cause a customer impact?" The correlation query is how you answer it at the data layer.

Your goal is to find time windows where both of the following are true simultaneously:

  • Telemetry shows a latency spike (average latency above a threshold, or a high error count)
  • Support tickets show a burst (unusually high ticket count in the same window)

A co-occurring spike + burst is strong evidence of a customer-impacting system issue. A spike without a burst (or vice versa) is a signal worth investigating too — you'll explore that in Challenge 3.

Must-do — Write the correlation join

  1. Open workshop-db in the Fabric workspace.
  2. Copy the starter query below into the KQL editor.
  3. Run it and identify at least one time window where a latency spike and a ticket burst co-occur.
  4. Note the Timestamp of that window — you'll need it for Challenge 3.
// Challenge 2 — Correlation join: spike windows ∩ ticket bursts
let spikeThresholdMs = 500;
let spikeWindows =
    SlotTelemetry_<>()
    | summarize AvgLatencyMs = avg(LatencyMs), ErrorTotal = sum(ErrorCount) by bin(Timestamp, 5m)
    | where AvgLatencyMs > spikeThresholdMs;
let ticketBursts =
    SlotTickets_<>()
    | summarize TicketCount = count() by bin(Timestamp, 5m)
    | where TicketCount > 3;
spikeWindows
| join kind=inner (ticketBursts) on Timestamp
| project Timestamp, AvgLatencyMs, ErrorTotal, TicketCount
| order by Timestamp asc
Tip: If the join returns no rows, try lowering spikeThresholdMs (e.g. 300) or reducing the ticket burst threshold (TicketCount > 1). The chaos engine injects incidents on a shared timeline — they may not have fired yet.

Stretch — Identify the incident ID

The chaos engine stamps an IncidentId on both telemetry anomalies and the tickets they triggered. Find the incident ID linking a spike to its tickets:

// Stretch: find the IncidentId linking a spike window to its tickets
let targetWindow = datetime('REPLACE-WITH-SPIKE-TIMESTAMP');
let targetWindowEnd = targetWindow + 5m;
let spikeIncidents =
    SlotTelemetry_<>()
    | where Timestamp between (targetWindow .. targetWindowEnd) and IsAnomaly == true
    | summarize by IncidentId
    | where isnotempty(IncidentId);
SlotTickets_<>()
| where Timestamp between (targetWindow .. targetWindowEnd)
| join kind=inner (spikeIncidents) on IncidentId
| project Timestamp, TicketId, CustomerTenant, Description, IncidentId
| order by Timestamp asc

Replace REPLACE-WITH-SPIKE-TIMESTAMP with the timestamp you identified in the must-do query. The IncidentId is the planted root cause your Part 3 agent will need to name.

Stretch — Customer impact: which tenants were affected?

// Stretch: which customers raised tickets during the spike window?
let targetWindow = datetime('REPLACE-WITH-SPIKE-TIMESTAMP');
SlotTickets_<>()
| where Timestamp between (targetWindow .. targetWindow + 10m)
| summarize TicketCount = count() by CustomerTenant
| order by TicketCount desc
