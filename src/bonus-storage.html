What you're about to do

You will create an Azure Storage account in your assigned resource group, configure Blob containers, and explore how Azure organises and tiers unstructured data at scale.

  • Create a storage account with LRS redundancy in your spoke RG.
  • Create a Blob container and upload a test file.
  • Explore hot / cool / archive access tier options and their cost implications.
  • Review the storage account's private endpoint configuration (reference only).

How it fits into enterprise Azure

Azure Storage is the universal persistence layer for IaaS workloads:

  • Managed disks are built on top of Page Blobs — the same storage service, just abstracted into a disk-shaped API.
  • Private endpoints bind a storage account to your spoke VNet, ensuring traffic never leaves the Microsoft backbone.
  • Lifecycle management policies automatically tier blobs from hot to cool to archive based on last-access time, reducing costs for rarely-accessed data.
  • Azure Backup uses a Recovery Services Vault backed by geo-redundant storage (GRS) — your VM backups are redundant across a region pair.

Lab steps — Create a storage account

The wizard has 7 tabs: Basics → Advanced → Networking → Data protection → Security → Encryption → Tags → Review + create.

  1. Open the portal link above. Click + Create → search for Storage account → Create.
  2. On the Basics tab — Project details:
    • Resource group: your assigned RG (shown in the banner)
    Instance details:
    • Storage account name: stworkshop (lowercase, no hyphens, globally unique)
    • Region: (US) East US 2
    • Preferred storage type: leave blank (optional guidance field, does not restrict the account)
    • Performance: Standard (leave default)
    • Redundancy: change to Locally-redundant storage (LRS) — the portal defaults to GRS; change it for this lab to keep costs low
    Click Next: Advanced.
  3. On the Advanced tab — note the Access tier setting under Blob storage:
    • Access tier: Hot (leave default) — Hot is for frequently accessed data; Cool/Cold are for infrequently accessed data at lower storage cost but higher retrieval cost
    • Leave all other settings as defaults
    Click Next: Networking.
  4. On the Networking tab — leave all defaults:
    • Public network access: Enable (leave default for this lab)
    • Public network access scope: Enable from all networks
    • Routing preference: Microsoft network routing
    Click Next: Data protection.
  5. On the Data protection tab — leave all defaults:
    • Soft delete for blobs, containers, and file shares is enabled by default (7-day retention) — this protects against accidental deletion
    Click Next: Security.
  6. On the Security tab — verify:
    • Allow enabling anonymous access on individual containers: unchecked (leave as-is — this prevents any container from being made publicly accessible, the secure default)
    • Require secure transfer: checked (leave default)
    • Enable storage account key access: checked (leave default)
    Click Next: Encryption.
  7. On the Encryption tab — leave all defaults (Microsoft-managed keys). Click Next: Tags.
  8. On the Tags tab — no changes. Click Review + create.
  9. On Review + create: verify Region = East US 2, Replication = LRS, Blob anonymous access = Disabled. Click Create.
  10. Once deployed, open the storage account → Containers → + Container. Name it workshop-data, set anonymous access level to Private.
  11. Upload any small file and verify it appears in the container listing.
  12. Explore Lifecycle management under Data management — review the rule types available (move to Cool, move to Archive, delete).
